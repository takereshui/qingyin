# Molan Light Music 1.3.14：QQ 授权收尾与播放队列修复

**版本**：1.3.14（versionCode 18）  
**构建日期**：2026-08-12  
**包名**：`im.molan.music`

## QQ 扫码确认后无响应的修复

此前实现只根据 QQ 登录轮询的跳转地址继续请求，并期待 QQ 音乐会话通过 HTTP 响应头 Cookie 返回。当前流程改为在扫码确认时先返回明确的“正在建立 QQ 音乐会话”状态，再于下一轮轮询中分阶段完成会话收尾。这样可以避免同步 WebView 原生桥接在多次网络请求期间表现为界面无反馈。

| 阶段 | 1.3.14 行为 |
|---|---|
| 生成二维码 | 保存 `qrsig`，并返回二维码和会话 ID。 |
| 等待/扫码 | 区分等待扫码、已扫码、已取消与过期状态。 |
| QQ 确认 | 解析成功回调的 UIN 与授权签名，先向界面返回 `authorized` 状态。 |
| 会话收尾 | 显式请求 QQ 登录确认端点，换取授权码，再提交 QQ 音乐登录请求。 |
| 凭据保存 | 从 QQ 音乐 JSON 响应解析 `musicid` / `musickey`，转换为应用私有会话字段并使用 Android Keystore AES-GCM 加密保存。 |
| 错误呈现 | 原生层返回 `stage` 和可读错误信息，登录弹层直接展示对应阶段而不是静默等待。 |

> 该链路仍依赖 QQ 音乐的非公开网页交互，因此最终成功率必须以真机、实际 QQ 账号及当前上游策略为准。应用不会向网页 JavaScript 暴露原始 QQ Cookie 或 QQ 音乐密钥。

## 播放队列与播放模式

播放器重构为可操作队列。播放器页面右上角的队列按钮将打开底部抽屉，显示当前队列、当前歌曲高亮、封面、歌手/专辑信息、点播按钮、单曲移除按钮、清空队列按钮与播放模式快捷切换。

| 模式 | 行为 |
|---|---|
| 列表循环 | 上一首/下一首按队列顺序切换，末尾与开头循环。 |
| 单曲循环 | 曲目自然结束时重播当前歌曲；手动点击“下一首”仍会继续切歌。 |
| 随机播放 | 不会立即重复当前歌曲；维护随机历史，因此“上一首”可以回退至真实的上一首随机歌曲，“下一首”可以前进回历史歌曲。 |

该交互参考 APlayer 对播放列表、循环和随机播放的公开设计原则。[1]

## 真机验收重点

先安装新 APK 并在“我的 → QQ 登录”中重新获取二维码。扫码确认后应先显示“QQ 已确认，正在建立 QQ 音乐会话”，随后成功关闭弹层并刷新合并歌单；如仍失败，界面会显示具体阶段，请保留该错误文字与时间以便继续定位。

播放任意包含多首歌曲的歌单后，打开播放器右上角队列按钮，依次验证队列点播、移除非当前歌曲、清空保留当前歌曲、顺序循环、单曲循环、随机历史的上一首/下一首行为。
