# Molan Light Music 1.3.15：QQ Cookie 回退与播放加载竞态修复

**版本**：1.3.15（versionCode 19）  
**构建日期**：2026-08-12  
**包名**：`im.molan.music`

## 修复一：QQ 授权确认后未返回 `p_skey`

真机反馈表明，部分 QQ 登录会话在首个 `check_sig` 响应中不直接返回 `p_skey`。1.3.15 不再把该 Cookie 视为唯一的前置条件，而是在保留二维码 `qrsig`、扫码确认回调参数和所有已收到 Cookie 的基础上执行兼容收尾。

| 调整 | 行为 |
|---|---|
| Cookie 链 | 每个 `Location` 跳转都手工请求并合并 `Set-Cookie`，最多跟随 4 跳。 |
| 双端点回退 | 先请求构造的 SSL `check_sig` 地址；如未得到 `p_skey`/`skey`，再请求 QQ 成功回调中原样返回的跳转地址。 |
| 无 `p_skey` 处理 | 继续发起 QQ 互联授权交换，以服务端响应作为最终判定，避免因单一 Cookie 缺失提前中止。 |
| 失败反馈 | 如果后续没有授权码或 QQ 音乐凭据，登录页会继续显示明确的后续错误，而非停留在“未返回 p_skey”。 |

> QQ 音乐二维码登录仍属于受上游策略影响的非公开网页交互。1.3.15 的目的，是兼容已确认实际出现的 Cookie 差异并把失败点继续前移到可见诊断；最终是否建立 QQ 音乐会话仍需在真机上以实际 QQ 账号验证。

## 修复二：`play()` 被新的 `load()` 中断

连续点歌、自动跳歌或队列切换时，旧请求可能仍在等待播放地址、缓存 Blob 或 `HTMLAudioElement.play()` Promise。新请求调用 `load()` 后，浏览器会拒绝旧 Promise 并产生“play() request was interrupted by a new load request”。

1.3.15 为每个 `playAt()` 调用分配递增加载令牌。每次跨异步边界（读取下载缓存、解析 QQ 音源、请求在线地址、读取音频缓存、调用 `play()`）都会确认令牌仍属于当前歌曲。过期请求会静默退出，不能再改写 `audio.src`、展示错误提示或触发自动下一首。被新 `load()` 正常中断的 `AbortError` 也会被识别为预期取消，而不是播放失败。

## 真机验收

重新生成 QQ 二维码并在 QQ 内确认。若失败，请发送登录页显示的**完整错误文字**；理想情况下错误将进入“QQ 未返回音乐授权码”“QQ 音乐授权失败，代码 ……”或“QQ 音乐未返回 musicid 或 musickey”等更精确阶段。

播放页面建议连续快速点击两首不同歌曲、点击队列内多首歌曲以及使用上一首/下一首。旧版本的 `The play() request was interrupted by a new load request` 不应再弹出或导致错误自动切歌。
