# APlayer 本地与线上歌曲匹配机制参考

参考仓库：<https://github.com/rRemix/APlayer>（`compose` 分支）。

## 关键机制

APlayer 将歌曲统一为本地与远程两种来源，并保留来源 ID / URL 与完整元数据。歌词、封面等扩展资源的缓存键并不只使用标题，而是综合来源类别、本地 ID 或远程 URL、标题、艺人和专辑后进行哈希，避免同名歌曲覆盖。

搜索关键字按可用元数据从强到弱生成：`艺人 - 标题`、`标题`、在艺人信息不可信时的`专辑 - 标题`，最后才对本地歌曲回退到文件名。空值、unknown、纯数字及特殊符号过多的元数据会被排除。

候选匹配先对本地歌曲应用时长硬门槛：两者时长差超过 4 秒直接拒绝。通过时长门槛后，按标题、艺人、专辑评分；标题和艺人均可用时权重为 0.60 / 0.40，标题、艺人、专辑均可用时权重为 0.50 / 0.35 / 0.15。综合分低于 55 的候选不接受。标题低于 30 分额外扣分。

文本评分包含全角/半角符号统一、多艺人拆分和最佳一对一匹配、编辑距离、标题共同前缀及版本标签识别（version、mix、edit、伴奏、inst、tv size）。

## 轻音适配方案

1. 为 Track 建立稳定的统一歌曲指纹：来源 ID / 本地 URI 只用于唯一性；用于跨源匹配的规范键基于标题、艺人、专辑、时长和可选本地文件名。
2. 本地歌曲扫描后建立内存索引；线上歌单、搜索与每日推荐进入播放前先查该索引。只有得分超过阈值且时长差不超过 4 秒的候选才替换为本地音源。
3. 播放优先级为：已下载的轻音文件 > 已扫描本地文件 > 已验证的在线直链 > 按当前音质请求线上解析 > 备用线路。
4. 歌词与封面缓存沿用“来源身份 + 规范元数据”的双重键，优先命中已有本地/下载曲目，再发起线上匹配。
5. 在线曲目与本地副本保持各自来源元数据；本地命中只改变播放载体，不篡改线上歌单或远程曲目的身份。
